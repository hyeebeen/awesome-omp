## 3. 定位（是什么、解决什么）

- 自述：「The most capable agent surface that ships」；「60+ providers · 31 built-in tools · 14 lsp ops · 28 dap ops」。（自述，数字不进清单正文，只引用并标自述）
- 核心卖点（README 01–21 节，自述）：带工具回调的 Python/Bun 代码执行；LSP 接入每次写入；驱动真实调试器（DAP）；TTSR 流式规则（正则命中中断并注入规则后重试）；带类型结果的子 agent（独立 worktree）；hashline（按内容哈希编辑）；内部 URL scheme（`pr://` `issue://` `agent://` `skill://`…）；ACP（在 Zed 等编辑器里驱动）；读取 8 种其他 agent 的规则格式（.claude/.cursor/.windsurf/.gemini/.codex/.cline/.github/copilot/.vscode）；`omp commit`；浏览器与桌面控制。
- 四种入口：交互 TUI、one-shot、RPC（stdio NDJSON）、ACP；另有 Node SDK。（README，已验证文档）
- 作者博客：「The harness problem」<https://blog.can.ac/2026/02/12/the-harness-problem/> （README 链接；正文未逐条核对，PARTIAL）

## 4. 与上游 Pi 的关系

- 上游 Pi：`badlogic/pi-mono` 现重定向到 **earendil-works/pi**（116,756★，MIT，最新 v1.3.0 2026-10-16 03:17）。repos API 返回 full_name=earendil-works/pi。已验证。

- 版本号体系独立（omp v18.x vs Pi v1.x）。已验证。
- 扩展兼容：omp 扩展 API 为 `ExtensionAPI` from `@oh-my-pi/pi-coding-agent`；有 `legacy-pi-compat.ts` 做宿主包兼容改写；manifest 里仍接受 `pi.extensions`，但 `.pi/extensions` **不是** omp 的原生发现目录（原生是 `.omp/extensions`、`~/.omp/agent/extensions`）。来源 docs/extensions.md、docs/extension-loading.md。已验证（文档）。→「Pi 包是否在 omp 上能用」需逐个验证，是高价值空白。
